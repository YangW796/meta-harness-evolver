You are working on a biology experiment-design task (BioDiscoveryAgent-style perturbation search). Your goal is to implement a better selection policy to identify genes (or gene pairs) whose perturbation yields extreme outcomes on a dataset-specific score.

## High-Level Goal (Perturbation Search)
There is a fixed library of perturbations (genes for most datasets; gene pairs for some datasets).
In each round, the policy must select a batch of NEW perturbations (no repeats). An oracle reveals the measured score and whether the perturbation is a "hit" under a dataset-specific hit definition.

The evaluation score is based on selecting strong perturbations under a limited query budget (default: 5 rounds × 128 per round = 640 queries), using metrics like:
- cumulative_hits
- normalized cumulative gain (ncg)

IMPORTANT: The final_score is based on delta_hits (new hits found in THIS run), not cumulative total_hits.

You may use any suitable algorithmic model to design the selection policy, including traditional algorithms, machine learning models, deep learning models, biological models, and mathematical models.

If gene search is available, you MUST use it to expand from strong anchors (hit genes and/or high-|score| genes).
Rationale: per-gene bandits cannot generalize in single-gene screens (each gene appears once); Achilles neighbors are
the intended mechanism to transfer signal from tested genes to untested genes.

Gene search argument meanings (MUST FOLLOW):
- query_gene: HGNC gene symbol used as the anchor. Choose from history (hit=1 and/or high-|score| genes).
- k: number of neighbor indices to return (<= k). Controls breadth of expansion.
- diverse:
  - False: return the most similar neighbors (exploit).
  - True: return the least similar neighbors (diverse exploration).

Guidance on diverse=True (IMPORTANT):
- diverse=True is useful for exploration but often reduces delta_hits by diluting hit density.
- Use diverse=True sparingly: only in early rounds (no hits or very few hits), ~10–20% of the batch.
- Once you have stable hits, use diverse=False for almost all of the budget.

Suggested stronger use of gene_search (optional but recommended):
- Upgrade from “take top-N neighbors per anchor” to “multi-anchor rank-weighted voting”.
- Pick anchors (prefer hit=1; if too few, add high-score genes).
- For each anchor, call gene_search(anchor, k=K, diverse=False).
- For each returned candidate at rank r, accumulate vote: vote += w_anchor / (r + 1).
- Select by highest vote to get consensus neighbors around multiple hits.
- Alternatively, train an online hit-probability model using Achilles features if you can access them.

If gene search is NOT available, do NOT use `candidate_index` proximity as a similarity signal unless you can justify that candidate ordering encodes biology.
