You are working on Project-4 (Active Search), a science task. Your goal is to implement a better Active Search selection policy to discover as many "good candidates" as possible under a limited query budget.

## High-Level Goal (Active Search)
There is a fixed candidate pool of 5000 candidates (rows) sampled from a larger CSV (by default, the dataset is selected by task name from BioDiscoveryAgent/datasets).

There is a hidden ground-truth label for each candidate:
- label=1 means "good candidate" (top-k by a ground-truth criterion).
- label=0 otherwise.

Ground-truth labels are derived ONLY from the dataset inputs (not from any hidden code):
- If the input CSV has a label column, it is used directly.
- Else if a topmovers_<TASK>.npy file exists alongside the CSV and the CSV has a Gene column, label=1 iff Gene is in topmovers.
- Else if the CSV has a numeric Score column, label=1 for the top_ratio fraction by abs(Score).

In each round, your policy selects batch_size NEW candidates (no repeats). An oracle reveals their labels. The evaluation score rewards finding as many positives as possible, as early as possible.
Final score is delta_precision = (delta_hits / delta_queries) scaled to [0, 100], where delta_* counts only the NEW queries made in this run (excluding any resumed history).

## What You Are Allowed To Change (ONLY MODEL)
Do NOT modify anything except the model implementation file.
Do NOT change any function signatures or IO behavior.

## Policy Interface (MUST KEEP EXACTLY)
Your model code must provide one of the following:
1) A module-level function:
   select(candidates, history, batch_size, seed) -> list[int]
or
2) A class with a select(...) method (class name can be SelectionPolicy / Policy / Model).

The evaluator will call select(...) each round.

## Input Semantics
candidates:
- A list of 5000 row-dicts (the full search space).
- Each row-dict maps column name -> value (numbers are floats, others are strings).
- Does NOT include the hidden label.
- Any column named Score is stripped before candidates/history are passed into your policy; do not rely on it.

history:
- A list of previously queried row-dicts.
- Each history row includes all original fields plus:
  - candidate_index: int (row index into candidates)
  - label: int (0 or 1)

batch_size:
- The number of NEW candidates to select each round (default: 100).

seed:
- An integer seed that may change each round.

## Constraints
- Do not import or call any hidden scoring function or labels.
- Do NOT attempt to read or infer labels from project files (especially index.py / compute_x). Treat labels as oracle-only. Your policy must be learned purely from (candidates fields, history labels).
- Do not return duplicates or already-selected indices; if you do, they will be ignored and replaced.
- The policy should run fast and be robust even when history is small (including empty at the beginning).

## Ideas You Can Explore
- Exploitation: fit a classifier/regressor from history_df and rank candidates by predicted probability of label=1.
- Exploration: uncertainty sampling (e.g., near 0.5 probability), diversity, clustering, bandits.
- Hybrid: mix exploitation and exploration with an annealing schedule.
